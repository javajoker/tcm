## 1. Conventions

| Topic | Rule |
|---|---|
| **Files** | UTF-8 JSON, keys sorted, 2-space indent, trailing newline, **no timestamps**: the same inputs yield byte-identical output. Never edit `data/` by hand — change the generator or the curated table and rebuild (`python -m scripts.kb.build_kb`) |
| **Envelope** | Most files are `{ "_meta": {…}, "items": [ … ] }`. `_meta` carries `count`, `description`, and file-specific notes (scoring formula, tier rule, status counts). Files with several collections use named top-level keys (e.g. `tongue.json`: `zones`, `features`) |
| **Ids** | Stable ASCII, never reused or renamed once released (saved reports and citations depend on them). Conventions per file in §3–§7 |
| **Bilingual text** | `{ "zh-Hant": "…", "en": "…" }`. `zh-Hant` is **always present**; `en` may be `null` (fall back to zh-Hant, see [i18n guide](i18n-guide.md)). Classical quotations are zh-Hant only (plus the source-script original) |
| **Script** | Everything user-visible is Traditional Chinese (Taiwan wording) converted from Simplified sources with OpenCC `s2twp` plus TCM post-fixes (裏→裡, 于→於) |
| **Status** | `status` on every reviewable record: `derived` · `curated-draft` · `draft` · `reviewed` (future) · `verified` (citations only). Meaning in §8.3 |
| **Citations** | Records reference quotations by id (`suwen-005-1`, `shanghan-035`, …); the text lives once in `citations.json` |
| **Panel dimension keys** | `"{organ}.{channel}"` (`脾.qi`, `腎.yin`), `liuxie.{風寒暑濕燥火}`, `product.{痰飲瘀食積}`, `bagang.exterior`. Organs: 肝 心 脾 肺 腎 膽 小腸 胃 大腸 膀胱; channels: `qi`, `blood`, `yin`, `yang` (signed, −3…+3) and `stasis` (0…3) |
| **Panel sign** | Positive = above the average healthy person; negative = below (zero is the norm). For **herbs and formulas**, values are the *change the item makes* to the panel of the person who takes it (e.g. `脾.qi +0.9`) |
| **Numbers** | Weights and effects are decimals rounded to 3–4 places at build time; engines must not assume more precision |

## 3. Evidence and diagnosis

### 3.1 `citations.json` — quotation registry (127)

| Field | Type | Meaning |
|---|---|---|
| `id` | string | `suwen-005-1` (book-chapter-n), `lingshu-046-1`, `shanghan-035` (Song-edition clause), `bencao-bianxue-18fan-1` … |
| `book`, `chapter` | string | Zh-Hant book and chapter |
| `clause_no`, `clause_no_verified` | int?, bool? | Present for 《傷寒論》 clauses; `false` = number follows the common Song edition and is not yet cross-checked |
| `quote_zh_hant` | string | Quotation shown to users |
| `quote_source_zh_hans` | string | Original text as found in the source file (the string that was matched) |
| `source_path`, `source_repo` | string | Path under `reference/sources/…` and the repository with its licence note |
| `verified` | bool | The source-script quote was found in the source text (all 127 `true`; `_meta.unverified` must be empty) |

### 3.2 `diagnosis/symptoms.json` — the 171-code registry

One namespace for symptoms (`S_*`, 111), tongue features (`T_*`, 32) and pulses (`P_*`, 28). Items: `id`, `kind` (`symptom` | `tongue` | `pulse`), `dimension`
(`cold-heat`, `sweat`, `head-body`, `stool-urine`, `diet-taste`, `chest-abdomen`, `ear-eye-throat`, `thirst`, `sleep`, `emotion`, `menses`, `face-skin`,
`voice-breath`, `qi-spirit-form`, `tongue`, `pulse`), `zh-Hant`, `en`. Tongue items add `tongue: { category, zone, meaning }` (`category`: `body | shape | special |
zone-body | coat | zone-coat`; `zone`: `all | tip | center | edge | root`); pulse items add `pulse: { optional: true, quality_coefficient: 0.5 }`.
The data-quality class is derived from the prefix: `T_` → *guided* (q = 0.7), `P_` → *pulse* (q = 0.5), otherwise *inquiry* (q = 1.0); see [SOP §4.7](diagnosis-sop.zh-TW.md).

### 3.3 `diagnosis/patterns.json` — 23 patterns

| Field | Type | Meaning |
|---|---|---|
| `id` | `EX1–EX4`, `SP1–SP6`, `LV1–LV4`, `HT1–HT3`, `LG1–LG2`, `KD1–KD2`, `QB1–QB2` | Stable pattern id; `group` is `external | spleen-stomach | liver | heart | lung | kidney | qi-blood` |
| `name` | bilingual | Pattern name |
| `weights` | `{ symptomId: 1…3 }` | Positive evidence weights (the pattern's core) |
| `against` | `{ symptomId: weight }` | Evidence against |
| `required_any` | `symptomId[]` (≥ 1) | If none is present, the score is multiplied by 0.5 |
| `max_score` | int | `Σ weights` (the denominator) |
| `elements` | `elementId[]` | 證素 that this pattern decomposes into (`PE_*`) |
| `panel_projection_per_degree` | `{ panelDim: unit }` | Contribution to the observed panel per degree (`degree = 3·Pct/100`) |
| `formulas` | `formulaId[]` | Linked formulas (must link back, §8) |
| `principle` | string | Treatment principle (治則/治法) in Chinese |
| `tongue_pulse_note` | string | Typical tongue/pulse for education (not scored) |
| `treatment` | `{ acupoints[], foods[], lifestyle }` | Per-pattern guidance (acupoints must exist in `treatment/guidance.json`) |
| `citations` | `citationId[]` | Theory basis |
| `status` | `draft` | |

Scoring (SOP §9.2, `_meta.scoring`): `Pct = max(0, Σ w·sev·q (present) − Σ v·q (against)) ÷ Σ w × 100`, ×0.5 without a `required_any` symptom.

### 3.4 `diagnosis/pattern-elements.json` — 24 證素

`id` (`PE_{location}_{nature}`), `location` (`全身 | 心 | 肝 | 肺 | 胃 | 脾 | 腎 | 表`), `nature` (寒 · 氣滯 · 氣虛 · 濕 · 火 · 痰 · 瘀 · 血虛 · 陰虛 · 陽虛 · 風),
`name`, `weights`/`against` (symptom weights taken as the maximum over the patterns that contain the element), `projection_per_degree`, `patterns` (back-links).
Used when no library pattern fits a compound presentation, and for the explanation of *which element* drives a pattern.

### 3.5 `diagnosis/tongue.json`

`zones[]`: `{ id (tip · center · root · edge · border · all), zh, en, classical: organs[], textbook: organs[] }` — classical column from 《傷寒指掌》 (verified), textbook column alongside (unverified);
`features[]`: `{ id (T_*), category, zone, name, meaning }` (32); `_meta.guidance`: when/what to avoid/how to see sublingual veins; `_meta.zone_citation`.

### 3.6 `diagnosis/pulse.json`

`pulses[]` (28): `{ id (P_*), name, group (depth · rate · rhythm · strength · tension · flow · length · width), yin_yang, feature, indications, source: { book, chapter, verified_heading } }`;
`positions[]` (6): `{ id (L-cun, L-guan, L-chi, R-…), zh, organs[] }`; `_meta.exclusive_groups` (e.g. `[P_FLOAT, P_SINK]`, `[P_SLOW, P_RAPID, P_HASTY]`),
`_meta.guidance` (education text, quality coefficient 0.5, rate bands: slow < 60, rapid > 90, modern normal 60–100).

### 3.7 `diagnosis/constitutions.json`

Nine constitutions `C_PINGHE, C_QIXU, C_YANGXU, C_YINXU, C_TANSHI, C_SHIRE, C_XUEYU, C_QIYU, C_TEBING`: `name`, `features[]` (symptom ids), `prior_nature[]` (證素 natures it leans towards),
`susceptibility { 風|寒|暑|濕|燥|火: 1|2 }`, `status`. Questionnaire items are intentionally **absent** (licence/wording decision SOP D6; see §9).

### 3.8 `diagnosis/red-flags.json` — 28

`{ id (RF_A_*, RF_B_*, RF_C_*), level (A emergency | B within 24 h | C out of intended scope), text: bilingual }`. `_meta.flow` records that the notice is shown in every profile and the flow continues.

### 3.9 `diagnosis/panel-schema.json`

The panel model: `organs.{zang, fu, element_of}`, `channels` (ranges), `liuxie` (six), `products` (痰 飲 瘀 食積), `location_organs` (證素 location → organs), `nature_projection`
(nature → panel targets; `{organ}` is a placeholder), `exterior_locations`, `derived` (formulas for `bagang.cold_heat`, `deficiency_excess`, `exterior`, `yin_yang`, `wuxing_function`),
`offsets` (definition of the primary and secondary offset).

## 4. Herbs and formulas

### 4.1 `herbs/herbs.json` — 704 herbs

| Field | Type | Meaning |
|---|---|---|
| `id`, `slug` | `herb-{slug}` | Stable id (pinyin slug) |
| `name`, `aliases?`, `latin` | bilingual / strings | `en` curated only for the MVP formula herbs |
| `category`, `functions[]` | strings | From the Pharmacopoeia entry (功能) |
| `siqi[]`, `temperature` | strings; −3…+3 | 四氣 and the signed warmth value |
| `flavors[]` | `{ flavor (辛苦甘酸澀鹹淡), element (五行), weight }` | 五味 → 五行 |
| `organs[]` | organ names | 歸經 mapped to the ten organ nodes |
| `effects` | `{ panelDim: Δ }` | **Benefit**: change to the panel |
| `harms` | `{ panelDim: Δ }` | **Burden**: e.g. bitter-cold → `脾.yang −0.25`, cloying → `脾.qi −0.25`, acrid-hot → `腎.yin −0.25` |
| `tags[]` | `辛散 滋膩 寒涼 苦寒 燥烈 通利 活血 甘壅 辛熱 收澀 升提 峻烈` | Property tags used by the tier rule and safety rules |
| `pregnancy` | `ok | ok-unreviewed | caution | avoid` | |
| `toxic`, `interactions[]`, `caution`, `dose_g_reference` | bool, class ids, string, `[min,max]` g | Safety facts (Pharmacopoeia) |
| `classical_formulas[]` | formula names | Where the herb appears in the classical corpus |
| `status` | `curated-draft` (94) \| `derived` (610) | Derived = produced by transparent rules in `herb_model.py` |
| `source`, `data_quality[]` | provenance | `source.entry_id`, `path`, `commit`; known data problems |

`herbs/herb-index.json` maps a zh-Hant name or alias → herb id (714 entries).

### 4.2 `formulas/formulas.json` — 33 formulas

| Field | Type | Meaning |
|---|---|---|
| `id` | `F_*` | e.g. `F_SIJUNZI` |
| `name`, `school` | bilingual; `經方 | 時方` | |
| `principle`, `rationale_zh`, `rationale_citations[]` | string, string, ids | Method and the explanation shown to users |
| `composition[]` | see below | Herbs with roles and weights |
| `classical_amounts[]` | `{ name, amount, unit, processing }` or `null` | Parsed from the **classical text** (9 formulas); for display only at L3; unit ∈ 两 个 枚 升 合 斤 |
| `panel_effect`, `panel_burden` | `{ panelDim: Δ }` | `Σ effective_weight × herb effects / harms` |
| `flavor_profile` | `{ flavor: share }` | Flavour shares (basis of the 55 % excess rule) |
| `core_indications[]` | symptom ids | Basis of the symptom-level fit (≥ 60 %) |
| `patterns[]` | pattern ids | Linked patterns (back-links required) |
| `tier`, `tier_reasons[]` | `A | B | C`, strings | **Computed**, never assigned (SOP §12.3) |
| `pregnancy`, `interactions[]`, `cautions[]` | | Aggregated safety facts |
| `modifications[]` | `{ id, result_name, when_symptoms[], add[{herb,name,role,typical_g}], remove[], source{book,verification}, status }` | Classical 加減 (e.g. 四君子湯 → 異功散 / 六君子湯) |
| `mvp` | bool | In the MVP candidate set |
| `source`, `kb_commit` | provenance | |
| `verification` | `{ composition_status, composition_check | classical, proportion_basis, role_status }` | `verified-against-classical-text` (9) · `verified-against-source-book` (18) · `partially-verified` (6, with the missing herbs listed) |
| `status` | `draft` | |

`composition[]` item: `{ herb, name, role (君|臣|佐|使), role_weight (1.0|0.6|0.35|0.15), proportion, effective_weight, typical_g, classical_amount?, note? }`.
Invariants: proportions sum to 1; **effective weights** (`proportion × role_weight`, renormalised) sum to 1; at least one 君 herb; every herb exists.

## 6. Policy, safety and treatment

### 6.1 `config/scope-profiles.json` — application configuration

`levels{L0–L3: { name, includes[] }}` · `notice_kinds{blocking_ack, inline, none}` · `dimensions{population[5], condition[7], state[3]}` ·
`profiles.{release, dev}`: `{ description, population{key: {level, notice}}, condition{…}, state{…}, features{show_acupoints, show_diet, show_dosage_reference,
show_formula_modification, show_herb_weights, show_tier_c}, safety_enforcement: "suppress_hard" | "annotate_only" }` · `resolution{effective_level, effective_notice, flow: "continue", …}`.
Every profile must define **every** dimension key (checked). `dev` must have level `L3` everywhere and keep every `blocking_ack` of `release` (checked).

### 6.2 `safety/rules.json` — 25 rules

| Field | Meaning |
|---|---|
| `id` | `R_*` (see SOP §13.2 for the table) |
| `applies_to` | One of `always`, `population[]`, `condition[]` (+ `medication_class[]`), `state[]`, `constitution[]` — when the rule is evaluated |
| `target` | What it tests: `herb_pregnancy`, `herb_interaction`, `formula_tier`, `acupoints`, `conflict`, `herb_in_user_allergy_list`, `flavor_share_over`, `herb_pairs`, `effect`, `output_level_max` |
| `severity` | `hard` (removed under `suppress_hard`) \| `soft` (annotated) |
| `message` | Bilingual text shown with the item or in the suppressed list |
| `citation?`, `condition?`, `reference?`, `note?` | Optional theory basis, extra predicate, textbook reference value |

Also: `dose_references` (age fractions for minors, elderly note — never shown as advice), `incompatibilities` (十八反 and 十九畏 pair lists; the 十九畏 list is textbook, unverified),
`pregnancy_acupoints[8]`. `_meta.clinical_review_required` lists what a practitioner must review.

### 6.3 `treatment/guidance.json`

`acupoints{ zhName: { code (WHO), meridian, pregnancy_avoid } }` (26) · `general{ text, source[] }` · `food_pregnancy_caution[]`. Location text and illustrations are not yet included (§9).

### 6.4 `glossary.json` — 139 terms

`{ zh-Hant, en, pinyin, domain, status: "needs-review" }`; domains: pulse, treatment, diagnosis, tongue, wuxing, zangfu, constitution, bagang, liuxie, herb, yunqi, substance, product, formula, bazi, nature, theory, season, calendar.

## 8. Integrity rules and review status

### 8.1 What `validate_kb.py` enforces today

Citations: every cited id exists; none unverified. Herbs: index entries resolve; every panel key is valid; every organ exists; `pregnancy` in the allowed set.
Formulas: proportions and effective weights sum to 1; every herb exists; every role valid; at least one 君; every core indication is a known symptom; every linked pattern exists **and links back**;
modification symptoms/herbs exist; rationale citations exist; `tier` in A/B/C. Patterns: every formula exists and links back; citations exist; projection targets valid; `required_any` non-empty;
acupoints exist. Rules: citations exist. Profiles: every dimension key defined and valid; `dev` opens everything and keeps blocking notices; `flow` = `continue`.
Yunqi: ten 民病 excerpts present with citations. After validation `selftest_patterns.py` checks that each of the 23 patterns ranks first for its own typical patient.

### 8.2 Additional checks required (tasks)

JSON Schema validation of every file · symptom ids used in `weights`/`against`/`core_indications`/`features`/`required_any` all exist · exclusive pulse groups reference real pulses ·
every `T_*` zone is a zone in `tongue.json` · `kb_commit` equals the pinned submodule commit · tier recomputed from composition equals stored tier (also asserted in the engine) ·
unit tests for `herb_model` rules · a **forbidden-wording lint** on all user-visible zh-Hant/en strings ([i18n guide](i18n-guide.md)).

### 8.3 Review status

| Status | Meaning | Allowed in `release`? |
|---|---|---|
| `derived` | Produced by transparent rules from structured sources | Yes, after a spot-check; shown with a "not yet reviewed" label in Sources |
| `curated-draft` / `draft` | Hand-curated table awaiting review | Only after the owning review (see [content review](content-review.md)); until then the release profile restricts the output level |
| `reviewed` | Signed off by a named qualified reviewer (record: reviewer, date, KB version, scope) | Yes |
| `verified` (citations) | The quotation was matched in the source text | Yes |

Nothing is `reviewed` yet; the release gate in the [release process](release-process.md) requires the review records listed there.

## 10. Extending the knowledge base

| To add … | Do |
|---|---|
| A **citation** | Add to `curated/citations.py` with the source path and the exact source-script quote; build verifies it appears in the text |
| A **symptom** | Add to `curated/symptoms.py` (id, dimension, bilingual names); add it to `questions.json`; use it in at least one pattern or exam rule |
| A **pattern** | `curated/patterns.py` (weights, against, `required_any`, projection, elements, formulas, citations); rebuild; the self-test must rank it first for its typical patient and report its closest confusable pair; add discriminating questions |
| A **herb** | Curated entry in `curated/herbs.py` (effects/harms, flags) — otherwise it is derived from the Pharmacopoeia rules |
| A **formula** | `curated/formulas.py` with roles and proportions; composition is verified against the classical text or source book; tier is computed; link patterns both ways |
| A **safety rule** | `curated/policy.py`; give `applies_to`, `target`, `severity`, bilingual `message`, and a citation if there is one |
| A **translation** | Fill the `en` field in the curated table; run the i18n lint; mark for review |

Every change ends with: `python -m scripts.kb.build_kb` (deterministic) → commit the regenerated `data/` together with the source change → the parity fixtures are regenerated ([tech spec §7.4](tech-spec.md)).

## 11. Compatibility and versioning

- **Schema version** (integer, in every file's `_meta.schema`, to be added): bumped on any breaking field change; the app refuses to run on a mismatch.
- **KB version** = content hash of the bundle manifest ([tech spec §5.1](tech-spec.md)); recorded in every saved report.
- **Additive changes** (new optional field, new record) do not bump the schema version. **Removing or renaming** fields or ids does, and ships with a migration note.
- Saved reports keep their own snapshot of the result, so a KB update never silently changes a past report.
